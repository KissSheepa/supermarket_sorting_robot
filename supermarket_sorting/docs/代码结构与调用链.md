# 代码结构与调用链（面试速查）

主控唯一入口：`client_task.py`。运行方式：`bash scripts/run_robot.sh`。
闭环：`建图扫描 -> 商品识别 -> 机械臂抓取 -> 跨障碍配送 -> 放置 -> 返程复取`，
多单循环直到订单完成或超时。

---

## 2. 谁调用谁（client_task.py 的静态依赖）

| 被调用方 | 在 client_task.py 中的位置 | 作用 |
| --- | --- | --- |
| `common.slot_map_j3` | import 第 52 行；`SlotMap()` 第 297 行；映射查询 1467/1471/1500/1524-1530 行 | 类别->货位映射、层高判定 |
| `common.task_parser` | import 第 55 行；`parse_task()` 第 446 行 | 订单解析 |
| `common.grasp_params_j5` | import 第 56 行；`resolve_grasp_params()` 第 738 行；`slide_for_z()` 第 790 行 | 抓取参数 |
| `common.arm_stow` | import 第 59 行；`apply_stow()` 第 301/895/1174 行；`UNSTOW_R` 第 794/804/1742 行 | 收/展臂 |
| `common.control` | import 第 78 行 | `step_func` 平滑 |
| `kinematics.mmk2_kdl` | import 第 79 行；`MMK2Kdl()` 第 298 行；`arm_to()` 里做 IK | 逆解 |
| `nav_return_dev.navigator` | 第 953 行延迟 import；`NavMppiNavigator()` 第 959 行 | 导航避障 |

延迟 import 的意义：ROS 环境缺失时 `--selftest` 仍能跑；导航只在真正送货时初始化，
省内存也便于失败降级（`except` 后停发速度并返回 False）。

```text
scripts/run_robot.sh
├── python3 -m perception.product_detect   -> /product/detections (商品世界坐标)
├── python3 -m perception.aruco_detect     -> /aruco/detections  (货位世界坐标)
└── python3 client_task.py                 (唯一主控)
      ├── 订阅 /supermarket_sorting/task  -> task_cb        (443)
      ├── 订阅 /product/detections        -> det_cb         (487)
      ├── 订阅 /aruco/detections          -> aruco_cb       (511)
      ├── 订阅 odom / joint_states / scan -> odom_cb / js_cb / scan_cb
      └── 定时器 -> tick()  (1655)  <<< 主状态机
```

### 状态机（tick 内的 18 个 phase，第 265-277 行定义）

```text
WAIT_TASK
  └─ NAV_TO_SHELF ── follow_route() 到货架前
       └─ SCAN_SHELF ── _start_sweep() -> _slide_for() -> _consume_perception()
       │                 -> _record_shelf_findings()  (1455/1421/1403/1496)
       └─ NEXT_SHELF -> (E,D,C,B,A 依次) -> REPORT
REPORT
  └─ PLAN_PICK ── _plan_nearest_pick() (718)  选最近可达货位
       └─ NAV_PICK ── follow_route() -> ARM_READY(1742 展右臂)
            -> DEPLOY_ARM(753) -> CREEP(1769 前移到抓取位)
            -> CLOSE_GRIP(1788 按类别合夹爪) -> LIFT
            -> RETRACT -> STOW_GRIP_HOLD(888)
            -> NAV_TO_DELIVERY(941)  <<< nav_return_dev MPPI
                 -> PLACE_ITEM(1204)  align->deploy->open->settle->clear->stow->retreat
                      -> NAV_RETURN_TO_NEXT(1099) <<< MPPI 返程
                           -> PLAN_PICK（下一单，循环）或 DONE
```

### 导航子链路（nav_return_dev）

```text
client_task._navigate_to_delivery / _navigate_return_to_shelf
  └─ NavMppiNavigator
       ├─ push_scan(scan, angle_min, angle_inc)  激光点进栅格
       ├─ step(pose, goal, scan)                 每 50ms 一次
       │     ├─ RollingCostmap                    滚动栅格(软膨胀 + 距离场)
       │     ├─ GlobalPathPlanner (A*)            参考路径

       └─ start_nav_log / write_nav_log           诊断日志 + 可视化
```

## 4. 四个可深讲的技术点

1. **建图与货位映射（`common/slot_map_j3.py`）**
   官方只保证"ArUco 货位固定、商品与货位对应关系每局随机"。所以先扫描建
   `类别 -> 货位` 映射：同一类别多次观测按 (货架/层/列) 投票，配合
   `MIN_MAP_SAMPLES` 过滤偶发误检，再在抓取前复核 ArUco ID 与类别一致。

2. **抓取参数化（`common/grasp_params_j5.py` + `kinematics/mmk2_kdl.py`）**
   按商品类别解析夹爪开合与抬升量，按层高解析 `slide`（躯干升降），
   目标姿态交给 KDL 逆解；够不到时用 `UNSTOW_R / STOW_R` 作为 IK 种子重试，
   避免 place/抓取卡在 unreachable。

3. **导航避障（`nav_return_dev/`）**
   A* 给参考路径、MPPI 在线滚动控制；代价地图软膨胀让机器人主动远离货架，
   矩形足迹做碰撞校验解决贴障与窄道擦碰；停滞检测触发重规划/返程兜底。

4. **参数统一与鲁棒性（`nav_return_dev/config.py` + 主控常量）**
   速度、代价权重、栅格分辨率、放置槽位（`DELIVERY_SLOTS`）、
   放置高度/前伸（`PLACE_Z` / `PLACE_FWD_DIST`）集中在两处以环境变量覆盖，
   便于复现和调参。
